# 成長、升級與昇華系統

> 狀態：設計草案，尚未實作。本文整理使用者提出的成長方式；整合模型與初版範圍屬建議，待確認後再實作。
>
> 本文擁有此玩法的設計與待決事項；專案定位見 [plan.md](../../plan.md)，工作狀態見 [handoff.md](../../handoff.md)。

## 系統階層與關係

```text
CombatAesthetic：動作對戰體驗
└─ 角色成長與昇華
   ├─ 經歷累積 ← 戰鬥、探索、有效訓練
   ├─ 成長內化 ← 休息、睡眠、冥想
   ├─ 突破判定 ← 累積條件、瓶頸、關鍵契機
   └─ 成長結果 → 角色能力、招式與表現回饋
```

成長規則決定能力變化，戰鬥提供經歷並使用成長結果，動畫、音效與 UI 呈現結果。存檔與連線權威判定是後續整合點，本草案不指定服務或程式介面。

## 需求與目標

使用者希望規劃多種升級方式，包含取得經驗時突破、睡眠或休息後成長、冥想領悟，以及勞累後經由睡眠恢復而提升。冥想與突破帶有修仙題材的聯想，但尚未決定採用修仙世界觀或境界命名。

目標是讓玩家理解「做了什麼而成長」及「成長何時生效」，同時容納實戰高潮與戰後休息的節奏。本階段整理玩法，不實作數值公式、技能樹、後端或共用套件。

## 成長方式

| 方式 | 成長來源 | 生效時機 | 預期體驗 |
| --- | --- | --- | --- |
| 實戰突破 | 戰鬥、探索或挑戰取得的經驗 | 取得經驗並達成突破條件時 | 當場領悟，產生戰鬥高潮 |
| 休息成長 | 先前累積但尚未內化的經歷 | 休息或睡眠完成後 | 冒險後整理所得，穩定變強 |
| 冥想領悟 | 已有經歷與修練成果 | 冥想完成後 | 主動整理經歷；可考慮選擇成長方向 |
| 鍛鍊後適應 | 有效訓練或挑戰帶來的負荷 | 勞累後充分休息或睡眠 | 付出、恢復與能力提升形成循環 |

這些方式是待整合的玩法需求，尚未決定全部同時採用，也未決定各自提升哪些能力。

## 建議整合模型

### 累積、內化與突破

```text
戰鬥／探索／有效訓練
          ↓
     累積成長潛力
          ├─ 休息、睡眠 → 內化為穩定成長
          ├─ 冥想       → 朝選定方向內化
          └─ 累積達標 + 關鍵契機 → 昇華突破
```

「成長潛力」暫指尚待轉化的經歷，不預設一定要顯示成另一條數值計量。休息與冥想可作為同一份經歷的不同轉化方式；同一份已轉化的經歷不應重複領取一般成長收益。突破是否另外消耗潛力仍待決定。

### 一般升級與昇華

建議一般升級負責逐步提高能力，昇華負責帶來玩法變化，例如新的招式銜接、格擋後反擊或技能效果改變。上述能力只是說明差異的例子，不代表已決定加入的技能。

如此可讓日常成長保持連續，也讓突破具有明確份量。替代方案是所有經驗達標都立即升級，流程較簡單，但休息與冥想需要另找用途。

### 疲勞與恢復

建議收益來自有效挑戰或訓練，疲勞表示恢復需求，不直接等同成長收益。睡眠轉化先前的累積，避免反覆空耗體力、睡覺就成為最有效的升級方式。

沒有新增經歷時，休息仍可恢復狀態，但不憑空增加成長潛力。有效挑戰的判定與重複訓練收益尚待設計。

## 建議初版與案例

初版建議先驗證「實戰累積 → 休息內化」及一次與能力相關的關鍵突破；冥想保留為後續成長方向選擇。休息先採短暫的遊戲內流程，不綁現實等待時間，具體時長尚未決定。

案例：角色經歷一段具有挑戰的戰鬥，累積成長潛力；休息後取得穩定能力提升。當角色具備突破資格並完成相關挑戰時，觸發一次昇華，開放新的戰鬥選項。再次休息不會重複取得同一份成長。

延伸案例：若加入冥想，玩家可用同一份待內化經歷選擇成長方向；需要確認這項選擇是否有趣，而非每次休息都多一道必要操作。

## 原型驗收建議

- 玩家能辨識成長來源，以及尚未內化與已生效的差異。
- 有效經歷可經休息轉化為成長，同一份收益不會重複發放。
- 單純空耗體力、反覆睡眠不會無限產生成長收益。
- 符合累積與契機條件時可觸發突破；不符合時不會錯誤觸發。
- 若採用升級與昇華分離，昇華後具有可實際使用的新戰鬥選項。
- 戰鬥中突破的回饋不遮蔽敵方動作或中斷必要操作。

這些是未來原型的驗收條件，尚未執行遊玩或程式測試。
